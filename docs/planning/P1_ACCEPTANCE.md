## Defects found during review

| Observed failure | Correction and verification |
| --- | --- |
| A Finder open request could fall between startup and listener registration. | Queue OS requests and drain the queue after registering the listener. A lifecycle regression covers multiple pending files in delivery order. |
| An obsolete failed render could leave a newer revision without its preview. | Check document identity and revision before surfacing the error. A regression covers rejection while a newer edit is pending. |
| Word import could silently drop CDATA or unknown entities. | Preserve CDATA, validate references and reject unrecognized entities. Test valid Unicode text and malformed input. |
| A PDF’s link targeted the local app URL and the rightmost table column was clipped. | Supply supported destinations during printing and use a print-specific table layout. Verify both external annotation and eighth column in the native output. |
| The original release bundle failed strict signature verification. | Tauri now ad-hoc signs the executable and its resource envelope for local macOS builds. The installed app passes codesign --verify --deep --strict. Public distribution still requires a distribution identity and notarization. [Tauri signing guide](https://v2.tauri.app/distribute/sign/macos/#ad-hoc-signing) |

The original 49 P0 tests remain in the 66-test run (41 Rust library, two dev-helper, 23 JavaScript). All passed. The 41 optimized Rust library tests also passed. Save revision ordering, dirty indicators, uncertain writes, file conflicts, symlinks, text formats and queued Close/Quit were exercised. A native Quit prompt kept the dirty file open after Cancel. The native crash exercise restored the unsaved draft, refused an overwrite, and preserved the recovered copy and externally changed original on disk.

The review covered tracked changes and new source, workflow and asset files against P0. No credentials, private keys, personal fixture paths or local recovery/build outputs were identified in the candidate files. The generated editor and desktop icons are intentional. The local build, PDFs, logs and test profiles are excluded. Strict Clippy with warnings promoted to errors still reports two baseline lints in the Word break match and Renderer constructor, both present at P0. Hosted CI remains pending.

## Visual identity

The application icon and wordmark match the supplied SVGs byte for byte. The desktop PNGs and ICO derive from the square icon. The ICNS contains ten 1×/2× representations with transparent outer margins, from 16 to 1024 actual pixels. Finder initially showed the old icon because the copy in Applications contained the P0 artwork. After installation, the bundle in Applications passed strict signature verification. Finder Get Info showed the new icon and the OS reported a single running Kladje at that path. Finder and running-app icon pixels matched. The owner confirmed the updated appearance after installation. The default and dark backgrounds use the same wordmark artwork in the blank preview. The print stylesheet keeps that branding outside document output.

## Decision and remaining acceptance

Ready to commit as a private, reviewed P1 checkpoint. No confirmed critical or high-priority defect remains in the exercised macOS workflows. Local everyday Markdown editing on the tested Mac is reasonable. Keep P1 release qualification open until a person verifies VoiceOver, real IME/RTL, increased contrast, default file association on a fresh account, populated mail/phone handoff and the outstanding offline/keyboard checks. A commit alone does not clear the roadmap gate for P2. The next feature phase after macOS acceptance is the existing P2 subset.

## PR description

**P1 single-document workflow and Kladje visual identity**

- Scope local rasters, gate remote images per document and sanitize preview and export HTML/MathML. Add relative image insertion, cross-file fragments, keyboard editor/splitter controls and portable HTML.
- Preserve P0 writes and recovery. Handle early Finder deliveries, stale render errors and Word XML content. Keep external PDF destinations and fit wide tables on the page.
- Package the supplied SVG identity with desktop icons, a screen-only empty-preview wordmark and a signed local macOS bundle.
- Validation on Apple silicon includes 66 passing automated tests, 41 optimized Rust tests, a clean editor rebuild, crash/conflict recovery, representative Word import, four-page native PDF proofs, and 33/116 ms p95 input/preview at 100 KiB.
- Remaining gates are human accessibility and input acceptance, clean installation/default associations, populated mail/telephone handlers, offline browser inspection, and hosted CI. Windows and Linux remain unverified. The app license, distribution signing and notarization remain open.

## Stabilization corrections

The macOS webview now requests ordinary Tab access to links and form controls. The document status exposes unsaved changes as text to assistive technology and updates only when its content changes. Compact windows wrap notices above the status bar. Ordered-list markers and syntax foregrounds were corrected after measurements found 3.04:1 for light list markers and 2.73:1 for light code comments. Regressions cover both theme palettes and dirty-state transitions. Inline code now uses a delimiter long enough for literal backticks, including mixed selections and padded content.
