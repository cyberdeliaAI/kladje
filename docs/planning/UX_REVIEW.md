# Kladje UX review

**23 November 2026 · desktop writer’s workflow.** The strongest part of the interface is that the source and its result are legible together. The biggest break in that experience came when a normal web link in the tutorial opened an error dialog. The most consequential usability defect is subtler. Under a delayed save the title can lose its edited marker while the latest text exists only in memory.

## What was observed

An Apple silicon Mac ran a debug build of the checked-in UI and native Rust commands in a temporary app bundle. Only the audit bundle identity and private webview setting differed for profile isolation. Observations include the dark first-run window at the configured 1240 × 800 size, its accessibility tree, the native menus, a synthetic unsaved note and the macOS print sheet. Long-session use, assistive-technology speech, Windows/Linux interaction and restored settings across launches remain unverified.

## Feedback, comfort and scope

Text size changes both panes, theme follows the system, and local preferences cover view, zoom, split and sync. These are sensible defaults. The native screenshot showed consistent typography and spacious paragraphs. The accessibility tree exposed headings, list structure, disabled task checkboxes, math content and the three layout states. Actual VoiceOver pronunciation, Tab escape from the editor, spell checking and keyboard focus after preview navigation need direct tests. A named source region does not establish that the editable field itself has an accessible name. See `editor-src/editor.entry.js:73`, `ui/index.html:16`, `ui/app.js:178`.

The status counter splits on whitespace and counts UTF-16 code units. It includes Markdown markers and treats an emoji or an unspaced sentence differently from what many writers expect. Define what the count represents and update only when the document changes. Expose optional line numbers and a wrap toggle after keyboard and file safety work. A separate focus or typewriter mode needs user evidence beyond existing source-only and fullscreen. See `ui/app.js:162`, `editor-src/editor.entry.js:301`.

For the next usability pass, ask a writer to recover a named draft while retaining an externally edited original, carry a local image to a different export folder, and navigate a long note with keyboard and screen reader. Observe the resulting files as well as the visible messages. These tasks give clearer release evidence than adding more controls.
