# Kladje project audit

**23 November 2026 · main at `15095ca` · version 0.1.0.** Kladje is already usable for everyday Markdown editing on the tested Mac. Its principal release blocker is the meaning of a successful Save. A controlled check wrote revision A to disk, typed revision B while the write was pending, and observed the application mark B clean. The same review found a non-atomic fallback and an unreliable recovery slot. Fix those contracts before expanding the editor.

Companion documents cover the [feature matrix](FEATURE_MATRIX.md), [native UX review](UX_REVIEW.md), [development roadmap](DEVELOPMENT_ROADMAP.md) and [product vision](PRODUCT_VISION.md).

No tags, stashes, existing planning directory or tracked CI workflow were present. Ignored Rust build products and generated Tauri schemas were present locally. The README describes product ambitions and build commands. The guide demonstrates syntax. ## Reliability findings

| Finding | What happens and why | User impact and repair direction |
| --- | --- | --- |
| **P0 · Save can acknowledge newer edits** | Observed with delayed I/O. `ui/app.js:569` snapshots text, awaits a write, then calls parameterless `markClean()` and clears recovery. `editor-src/editor.entry.js:136` marks whatever document is current at completion. Save and Save As bypass the operation guard at `ui/app.js:730`. | A later edit can close without a prompt. Out-of-order completions can also update another document’s identity. Acknowledge only the saved revision, serialize competing saves and revalidate before closing or replacing a buffer. |
| **P0 · Failed staging can still change the original** | Observed. `src-tauri/src/fileio.rs:68` normally writes and syncs a neighboring file, copies permissions best-effort, then renames it. On any error, lines 93–99 attempt a direct write. A probe denied the normal staging route using a disposable conflicting temp entry. Save returned success and changed the original. | Direct writes can truncate or partially replace content. Temp names also repeat for the same destination/process. Use unique exclusive staging, handle replacement failures visibly, preserve metadata by policy, and define directory-sync guarantees. |
| **P0 · Link identity changes on Save** | Observed on macOS. With a normal writable symlink, rename replaced the link with a regular file while its target retained the previous text. `src-tauri/src/fileio.rs:84`. CLI open canonicalizes paths, while the dialog read returns the supplied path. `src-tauri/src/main.rs:61`, `:250`. | Different open routes can behave differently for the same document. Preserve supported link semantics or require Save Copy where the target is ambiguous. Include hard links, permissions and extended metadata in the policy. |
| **P0 · External edits can win or disappear invisibly** | Focus triggers an mtime check in `ui/app.js:688`. Missing files and equal millisecond timestamps are ignored. Clean reload checks identity before the second read, not after it. In a delayed-read probe an intervening edit was replaced and marked clean. The write command accepts only path and content. `src-tauri/src/main.rs:73`. | Another program can overwrite the baseline without a focus change, or the app can replace newer user text. Verify disk identity/version at save and recheck buffer identity/revision after each await. Offer preservation of both versions when resolution is uncertain. |
| **P0 · Recovery can erase the last good snapshot** | Observed by injecting a storage rejection after one successful write. `ui/app.js:139` schedules a full-text snapshot after 900 ms of inactivity. Lines 670–683 remove the prior snapshot on error. One origin-wide key holds all drafts. Restoration reads current disk mtime, and a failed restore prompt proceeds to cleanup at lines 858–881. | Continuous typing, quota, multiple instances or a changed original can defeat recovery. Keep bounded private per-document snapshots, a maximum interval, the original disk baseline, safe migration and clear failure feedback. |
| **P0 · Dropped or selected non-text files can become writable text** | Source. Unknown drops go through `openPath` at `ui/app.js:621`, including an image. File → Open also uses text reading for All Files. `src-tauri/src/fileio.rs:36` falls back to byte-to-character conversion. The original path is retained on Save. | A later Save can replace the original binary with UTF-8 bytes. Classify before discard/open, reject ambiguous binary data, and use explicit import or insertion workflows. |
| **P0/P1 · Format changes are broader than the README implies** | Source and decoder tests. UTF-8 BOM is stripped without a conversion flag. UTF-16 BOM and Latin-1 decode to Unicode. UTF-16 conversion can use replacement characters or drop an odd trailing byte. One CRLF anywhere sets the entire document’s output mode. CR-only becomes LF. `src-tauri/src/fileio.rs:34`, `ui/app.js:498`, `:527`, `:569`. | This preserves uniform LF or CRLF but can change the byte representation of existing files. Store explicit encoding/BOM/EOL metadata, confirm potentially lossy saves and show the consequence at save time. |
| **P1 · Import may silently lose layout or content** | Observed. The Word parser stops on XML errors, and parts are read with a 128 MiB cap without distinguishing overflow. `src-tauri/src/import.rs:82`, `:347`. A partial XML fixture returned its first paragraph as success. Its hard-break writer emits two trailing spaces and `tidy` removes them, also affecting fenced content. Lines 49, 451, 481. An HTML break fixture also became a soft newline. No embedded-media extraction was found. | Original files survive explicit Import. The converted document can appear complete when it is incomplete. Return explicit fatal/partial outcomes, preserve semantic whitespace and document supported Word features. |
| **P1 · Export and preview can disagree about assets** | Observed core export retains an image reference such as `img/chart.png`. Preview resolves from the open file directory. Export receives a title and Markdown, with no source directory for asset resolution. Print uses lazy images and waits a fixed 60 ms after render. `ui/app.js:346`, `:638`, `:658`, `src-tauri/src/export.rs:8`. | Styles travel with the HTML, but moving the export can break its images. Choose asset portability semantics. Ensure print uses the intended current document and settled resources. |
| **P1 · Pending opens and reloads lack a common coordinator** | Source. Startup takes a single pending path before JS registers the open listener. Later requests use a single mutable slot. Busy guards can drop events after taking them. Recovery also takes precedence over a pending request. `src-tauri/src/main.rs:40`, `:241`, `ui/app.js:547`, `:826`, `:858`. | A user can double-click a file and see a different document with no explanation. Queue requests or explicitly report deferral, preserve dirty prompts, and test startup with both recovery and an OS-open request. |

## Security, permissions and resource use

- **Observed link failure.** The guide’s ordinary HTTPS link reached a native denial. The capability grants `opener:allow-open-url` without URL allow entries. The locked opener checks its allowed scopes before hand-off. Grant only the intended HTTP(S), mail or telephone schemes, with a native test for each supported behavior. `ui/app.js:373`, `src-tauri/capabilities/default.json:12`.
- **Preview trust boundary.** Ammonia and CSP provide meaningful defenses. Existing tests cover script/handler removal, restricted HTML, safe elements and distinct ID policies. MathML is inserted *after* cleaning, using string placeholders, and two private-use characters are stripped from source during rendering. Review generated markup in its final context, use structured insertion where feasible, and include MathML and private-use Unicode in regression fixtures. The audit found a reason to validate final markup. Script execution was not observed. `src-tauri/src/markdown.rs:78`, `:133`, `:304`, `:333`, `:460`.
- **Local files and remote images.** The main window has global Tauri APIs, the asset protocol uses a broad wildcard scope, and image CSP allows HTTP(S). Opening content can therefore cause network image requests. The app’s custom read/write IPC commands accept paths from the UI. Scope access around the user-selected document and approved assets, make remote loading explicit, and retain a narrow opener policy. `src-tauri/tauri.conf.json:10`, `:22`, `src-tauri/src/main.rs:60`, `ui/app.js:346`.
- **Development helper.** The example listens on loopback and implements general filesystem operations without a per-session authorization boundary. It also allocates request bodies from a declared length. Keep it development-only, restrict it to a fixture directory and bound input sizes before using it for routine automation. This is a source review of the helper. `src-tauri/examples/devserver.rs:77`, `:93`, `:118`, `:150`.
- **Release failure handling.** Release sets `panic = "abort"`, so `catch_unwind` cannot recover from a panic in that profile. UI render errors are mostly reported to a logger that emits only in debug. Decide which render failures should be returned as typed errors, keep source available on failure, and test the actual production profile. `src-tauri/Cargo.toml:26`, `src-tauri/src/markdown.rs:65`, `ui/app.js:280`, `src-tauri/src/main.rs:106`.

### Performance measurements

One release-mode Apple silicon run timed five renders per size with a shared renderer. Each fixture repeated a 105-byte Markdown section 32, 512 or 4,096 times. The section contained a heading, a short paragraph with emphasis and a relative link, and a three-item list. Sizes below are bytes. Times are sample medians, useful for tracking this particular input. Renderer initialization measured 4.35 ms. A separate run of the core probe peaked at about 61.7 MiB RSS, including rendering and fixture checks. Startup-to-editable, idle memory of the desktop process tree and typing latency were not measured.

| Markdown input | Generated preview HTML | Median Rust render |
| ---: | ---: | ---: |
| 3,360 | 17,102 | 0.72 ms |
| 53,760 | 284,278 | 10.48 ms |
| 430,080 | 2,343,046 | 63.08 ms |

The UI already coalesces renders, adapts its delay, reuses unchanged leading/trailing DOM blocks, and maps scroll by source positions. Tagged blocks above 256 KiB skip highlighting. Those choices are worth preserving. Entire documents still cross IPC, parse and sanitize on each render. The frontend parses a full detached DOM, compares serialized block keys and refreshes source positions. Cursor movement can re-stringify and recount the document, and a single edit can schedule two statistics updates. A load calls `renderNow` even in editor-only mode. The 64 MiB text input ceiling is an admission limit. Resource use scales with block count and output expansion. Profile end-to-end before choosing incremental parsing. First avoid redundant scans, cap expensive preview work, and measure large prose, giant fences, tables and images separately. `ui/app.js:130`, `:159`, `:259`, `:300`, `:421`, `:514`, `src-tauri/src/fileio.rs:8`, `src-tauri/src/markdown.rs:24`.

## Test, release and maintenance priorities

The existing library suite exercises useful examples. Little coverage reaches the boundary between a real editor revision, a pending native command and the filesystem. The most cost-effective new seam is a deterministic document controller with controllable read/write promises. Reuse the CodeMirror adapter and the same Rust command implementations in tests. Keep native smoke coverage for app permissions, close handling, printing and file associations. The [roadmap](DEVELOPMENT_ROADMAP.md) includes the failure and platform acceptance cases.

Keep plain JS, Tauri, CodeMirror and Rust. Split responsibilities where a regression justifies the change. Centralize open/import/drop classification, path/fragment handling and O/S-specific file decisions. Keep native menu IDs, JS action IDs and enabled/checked state synchronized through a checked command inventory or simple consistency test. Share response types/semantics between production IPC and the developer shim. Avoid a second Markdown parser just to generate an outline. Reuse the existing renderer’s headings and source positions.

The configuration requests installers for all targets and associates four Markdown extensions. The chooser additionally accepts TXT and MDX, but no MDX/JSX execution or dedicated rendering is configured. Document supported formats precisely. Windows, Linux, installer updates, file associations, clean installation, spell checking, screen-reader speech, sign/notarize steps and long-running memory behavior remain release checks. Package metadata, icons and target settings describe the intended release targets. `src-tauri/tauri.conf.json:42`, `src-tauri/src/main.rs:238`, `ui/app.js:29`, `README.md:29`.

## Executive summary

| # | Most important finding | Most valuable improvement |
| ---: | --- | --- |
| 1 | An older write completion marks newer text clean. | Track document identity and saved revision through every asynchronous operation. |
| 2 | Atomic replacement falls back to writing the original in place. Saving a symlink replaces the link. | Fail safely, preserve file identity and offer Save Copy. |
| 3 | Focus-only mtime checks miss conflicts, and a delayed reload can discard recent input. | Verify the disk baseline at Save and protect both versions. |
| 4 | A failed recovery write erases the previous good draft. | Store private, versioned recovery snapshots and retain the last successful one. |
| 5 | The file-open path accepts binary input and may change encoding or line endings on Save. | Classify inputs before replacement and disclose or preserve byte-format changes. |
| 6 | The native guide’s HTTPS link fails, while image loading has broad local and network access. | Scope external links and document assets independently, with explicit remote-image consent. |
| 7 | A useful Markdown engine, editor and PDF path already work on macOS. | Preserve them and qualify real editing, keyboard access and printing on each release platform. |
| 8 | Word import can succeed with partial content, and exported HTML can lose relative images. | Report conversion fidelity and make exported assets travel with the output. |
| 9 | The renderer is fast for short fixtures, but input, HTML, DOM and statistics costs grow with the document. | Measure desktop latency and memory, cache statistics and degrade preview gracefully. |
| 10 | Nineteen library tests pass. Document workflows and distribution lack equivalent coverage. | Add lifecycle failure tests, reproducible bundles and native release gates before adding Recent and outline. |

**Five biggest risks, in order.** (1) Losing the last edits while showing a clean document. (2) Damaging the existing file on a failed or misdirected save. (3) Losing the only recovery copy or overwriting an external version. (4) Loading resources beyond what the writer expected from an offline preview. (5) Shipping an unqualified platform or large-file claim based on a passing Rust suite.

**First development phase.** Deliver P0 steps 1 and 2 together. A failed write must leave the original intact, and a successful write must acknowledge exactly the revision it saved. Follow immediately with conflict handling and recovery. The [roadmap](DEVELOPMENT_ROADMAP.md) gives separate acceptance tests.

**Owner decisions.** Confirm manual-save and recovery/retention defaults, encoding and link-file semantics, local/remote image and portable HTML policy, the one-document window model, and which operating systems must qualify together at v1. Proposed defaults and trade-offs are in the [product vision](PRODUCT_VISION.md).
